# @mercury-fw/plugin-types

The contract a [Mercury](https://github.com/lucabro81/mercury-fw) tool plugin implements: `Plugin` (with the one-sentence `description` of what it does, which the model answers "what can you do?" from), `PLUGIN_API_VERSION` and the types around them (what `build()` receives and returns, the context layer it adds to what the model reads and the knobs an admin can change on it (`KnobSpec`), the hooks after a turn, on what each turn and resolved confirmation left (`TurnRecord`, with `archivedMessages`, the messages an archive keeps of one; a turn's answer carries its `output`, a `TurnOutput` of an `OutputMode`, when the instance asks for one other than text) and when a session closes, the job for work nobody waits on, the handle of a model the app declared, skills, lists handed to the user, the texts a person sees: `Messages`, `Params`, `Translate`), and the primitives a plugin can use while it runs: what it asks for in `needs` (`PluginNeed`: the vector index, the conversation store and its `StoredMessage`, the shape of everything archived, the embedding model), the background model, work every day at a set time (`Daily`), people's profiles (`Profiles`), the tool log (`ToolLog`), and the way a plugin keeps a conversation (`ConversationOwner`, the `CompressionReport` it gives back when it shortens one, and `formatTurnStamp`, the line before each of the person's messages). Plugin authors get it through [`@mercury-fw/kit`](https://www.npmjs.com/package/@mercury-fw/kit); it's a package of its own so the core and the plugins share one definition.

On Mercury's documentation site: [the contract's reference](https://lucabro81.github.io/mercury-fw/reference/api/types/plugin-types/).
