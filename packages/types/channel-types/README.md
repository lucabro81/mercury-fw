# @mercury-fw/channel-types

The contract a [Mercury](https://github.com/lucabro81/mercury-fw) channel implements: `ChannelPlugin`, `CHANNEL_API_VERSION`, the provider and sink a channel drives a turn through, the `Principal` it builds for whoever sent the message (only the core reads it, tools never see it), the confirmation helpers (`detectPendingConfirmation`, `ConfirmReply`, `ResolvedConfirmation`: what `confirm` and `resolveConfirmation` hand back, the text in the person's language) and read getters the core injects (both take the caller's `Principal`, so a token resolves only for whoever staged it and a read returns only the caller's data), and the auth-provider contract (`AuthPlugin`, `AUTH_API_VERSION`, `Authenticate`): an app declares one provider as `auth`, and a channel whose callers bring their own credentials gets it as `ctx.authenticate`. The texts a channel shows a person itself come from `ctx.i18n.forRequest(principal, hint)` in their language, its English declared in the channel's `messages` under its name; `InboundTurn.languageHint` hands the core the language the person's client asks for, `InboundTurn.timeZoneHint` the time zone it's in (the turn's time is stamped in it when the person saved none), `ctx.settings` saves the person's own settings for a channel with a settings area (`setTimeZone`), and `finalize(text, { pendingNote })` says when the text is the core's stand-in for an answer the model didn't write. This is version 6 of the channel contract. Channel authors get it through [`@mercury-fw/kit`](https://www.npmjs.com/package/@mercury-fw/kit).

On Mercury's documentation site: [the contract's reference](https://lucabro81.github.io/mercury-fw/reference/api/types/channel-types/).
