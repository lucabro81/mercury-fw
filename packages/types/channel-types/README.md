# @mercury-fw/channel-types

The contract a [Mercury](https://github.com/lucabro81/mercury-fw) channel implements: `ChannelPlugin`, `CHANNEL_API_VERSION`, the provider and sink a channel drives a turn through, the `Principal` it builds for whoever sent the message (only the core reads it, tools never see it), the confirmation helpers (`detectPendingConfirmation`, `ConfirmReply`, `ResolvedConfirmation`: what `confirm` and `resolveConfirmation` hand back, the text in the person's language) and read getters the core injects (both take the caller's `Principal`, so a token resolves only for whoever staged it and a read returns only the caller's data), and the auth-provider contract (`AuthPlugin`, `AUTH_API_VERSION`, `Authenticate`): an app declares one provider as `auth`, and a channel whose callers bring their own credentials gets it as `ctx.authenticate`. It also holds the trace-sink contract (`TraceSinkPlugin`, `TraceSink`, `TraceEvent`, `TRACE_SINK_API_VERSION`): an app declares one sink as `traces.sink`, whose `build({ env, log, dir })` returns a `TraceSink` with `write` and `flush`; the core hands it every event already cut to the instance's level and with the person and the session pseudonymised. A sink's author gets it through `@mercury-fw/kit`. And the vector-index contract (`VectorIndexPlugin`, `VectorIndex`, `VectorPoint`, `VectorSpaceSpec`, `VectorWhere`, `VECTOR_INDEX_API_VERSION`): an app declares one index as `vectorIndex`, whose `build({ env, log })` returns named spaces of points the core `ensure`s, `upsert`s, `query`s by nearness, `scroll`s in order and rewrites (`setPayload`), always within what an equality `where` selects; the core computes the vectors. And the conversation-store contract (`ConversationStorePlugin`, `ConversationStore`, `StoredMessage`, `StoredTitle`, `CONVERSATION_STORE_API_VERSION`): an app declares one store as `conversationStore`, whose `build({ env, log })` returns a store the core gets `ready`, `append`s messages to, reads one conversation from in time order (`messages`, paged by `cursor`) or a person's newest messages from (`recent`), and keeps each conversation's title in (`setTitle`, `titles`); every read is scoped to one person. The texts a channel shows a person itself come from `ctx.i18n.forRequest(principal, hint)` in their language, its English declared in the channel's `messages` under its name; `InboundTurn.languageHint` hands the core the language the person's client asks for, `InboundTurn.timeZoneHint` the time zone it's in (the turn's time is stamped in it when the person saved none), `ctx.settings` saves the person's own settings for a channel with a settings area (`setTimeZone`), `ctx.conversations` renames the person's conversations for a channel that lists them (`rename`, its `RenameOutcome` saying when the conversation isn't theirs), `ctx.contextAdmin` reads and changes the instance's context for a channel with an admin area, only for people holding `mercury.context-admin` (`read`, `update`, `changes`, their `ContextAdminOutcome` saying why not), absent without a `context` and on an older core, and `finalize(text, { pendingNote })` says when the text is the core's stand-in for an answer the model didn't write. `ChannelHostReads.conversation`, `conversations` and `memoryScroll` are there only when the agent keeps what they read (a conversation store, a vector index). This is version 7 of the channel contract. Channel authors get it through [`@mercury-fw/kit`](https://www.npmjs.com/package/@mercury-fw/kit).

On Mercury's documentation site: [the contract's reference](https://lucabro81.github.io/mercury-fw/reference/api/types/channel-types/).
